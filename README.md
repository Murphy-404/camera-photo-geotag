# 相机照片定位工具

用带 GPS 的手机照片或 GPX 轨迹给相机 JPEG 批量补位置。命令行会列出定位依据、坐标与时间差，确认后在指定目录生成回验过的 JPEG 副本。文件处理在本机进行。

## 使用

需要 Node.js 22 或更新版本。在本目录安装依赖：

```powershell
npm.cmd ci
```

分别准备手机参考照片目录和相机 JPEG 目录。先查看建议，再导出：

```powershell
node geotag.mjs --phone 'D:\照片\手机' --camera 'D:\照片\相机' --camera-offset=+08:00 --shift 20 --window 60 --preview
node geotag.mjs --phone 'D:\照片\手机' --camera 'D:\照片\相机' --camera-offset=+08:00 --shift 20 --window 60 --out 'D:\照片\定位副本'
```

- 将示例中的偏移改为实际拍摄时区。相机慢 20 秒时用 `--shift 20`，快 20 秒时用 `--shift=-20`。如果相机的 EXIF 已记录正确时区，可省略 `--camera-offset`。手机 EXIF 缺时区时可用 `--phone-offset=+08:00` 指定该批照片拍摄时的偏移。跨时区或相机期间调过时间的照片分批处理。
- 一次扫描各目录的直接文件。相机侧处理 `.jpg` 和 `.jpeg`。手机侧读取带 EXIF 拍摄时间和 GPS 的 JPEG，也可读取有相同 EXIF 字段的 `.heic` 文件。当前端到端样本只覆盖 JPEG。导出手机照片时需选保留原始元数据的方式。
- 匹配窗口默认前后各 60 秒。取窗口内最近的参考照片。若同一窗口内有参考位置距最近参考点超过约 100 米，这张相机照片会被标为冲突并跳过。仍需检查时间接近的照片是否在同一地点拍摄。
- 输入如 `1,3` 导出指定副本，或输入 `all` 确认当前建议。直接回车取消。已有 GPS、缺少可靠时间、无候选和冲突项会跳过。已有同名目标文件时保留它并报告失败。请输出到支持硬链接的本地磁盘，如 NTFS，以原子方式发布已验证的副本。
- 每张副本回验实际坐标、JPEG 图像数据、方向和拍摄时间。退出码 `0` 表示命令正常结束，`1` 表示未能启动或确认输入无效，`2` 表示至少一张相机照片读取或导出失败。一批内成功生成的副本可以继续使用。

### 用 GPX 轨迹定位

```powershell
node geotag.mjs --gpx 'D:\照片\轨迹.gpx' --camera 'D:\照片\相机' --camera-offset=+08:00 --shift 20 --window 60 --max-gap 120 --preview
```

预览后，去掉 `--preview` 并加上 `--out 'D:\照片\定位副本'`，按提示确认导出。

- 每次选择一个 UTF-8 GPX 文件或一组手机照片。GPX 模式读取带显式时区的轨迹点，保留原分段，并使用 WGS-84 坐标。
- 推荐结果标为精确实测点、插值估计或最近实测点。插值要求照片时间与两侧采样均在 `--window` 内；只有一侧在窗口内时可用该实测点。出现轨迹分段、无效点、时间倒序、采样间隔超过 `--max-gap` 或表观速度超过 100 米/秒时，工具跳过该空档。轨迹范围外的照片跳过。
- 同时刻出现不同坐标，或其他轨迹段的候选位置距首选位置超过约 100 米时，标记冲突并跳过。两个时间阈值是初始默认值，可按采样频率调整。输入目前使用轨迹 `trkpt` 的时间和经纬度。

## 验证

```powershell
npm.cmd test
```

测试从 `fixtures/synthetic.jpg` 生成元数据样本。图片为程序生成的 16×16 像素图，无真实照片或位置记录。Windows 测试还使用系统图像读取器打开导出结果。元数据读写使用 [ExifTool](https://exiftool.org/)，图像编码数据通过其 [ImageDataHash](https://exiftool.org/TagNames/Extra.html) 核对。

当前本地命令行支持手机参考照片和 GPX 两条 JPEG 流程。后续范围包括 RAW/XMP、可视化批量复核及任务恢复，并按目标设备和编辑软件验证兼容性。
